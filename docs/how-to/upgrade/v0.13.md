# Upgrade to v0.13

Unreleased. The configuration moves to version 2 (`audit.truvity.github.io/<kind>/v2`), secrets
are named by `...Secret` and found through one declared source, and the ingest side of the
Pulumi library needs `Senders`. Version 1 is read for **one minor**, so a v0.13 installation
runs with its old files; this page is the migration to version 2 and the changes that are not
optional.

## Purpose

Move an installation (Kubernetes, AWS Lambda or both) from v0.12 to v0.13 without a window in
which a function or pod refuses to start, and without a secret in a function's environment.

## Preconditions

- You run v0.12 (or an earlier release that already reads a file; before v0.6 see
  [the v0.6 upgrade](v0.6.md)).
- For Lambda: the Pulumi stack, and the SSM parameters' values.
- For Kubernetes: the application chart's values for the `audit:` block.

## Before you start

- **Roll the binaries first, then the layer that says `v2`.** A binary of the previous release
  reads version 1 only, so a configuration layer that says `audit.truvity.github.io/.../v2`
  under a v0.12 function makes it refuse to start. The library renders the configuration for
  its own release's schema; library and zip must be the same release (the preview refuses a
  mismatch unless `Guards.AllowVersionSkew`).
- **`secrets.source: env` is refused on AWS Lambda at run time.** A process that finds
  `AWS_LAMBDA_FUNCTION_NAME` set will not read a secret from the environment, whatever its file
  says. A version-1 `...Env` that the loader converts to `source: env` therefore **fails on
  Lambda too**. A Lambda that read a secret from a variable must move to `source: ssm` before it
  can run this release. A `...Env` key in `Writer.Keys` is now refused at preview.
- **`Ingest.Senders` is required** when the ingest side is on, and the queue policy now also
  **denies** `sqs:SendMessage` to every principal not named. A stack that named none now fails at
  preview. `Senders` and `Redrivers` must be the ARN of an IAM role or user: no assumed-role
  session ARN, no `sts` ARN, no bare account id, no wildcard.
- **The chart's readiness probes read `/readyz`** (with `timeoutSeconds: 3`); liveness stays on
  `/healthz`. A readiness probe overridden in your values must follow, and every golden you keep
  changes by those two lines.
- **The OTLP extension's settings are renamed.** The library sets `AUDIT_OTLP_ISSUER`,
  `AUDIT_OTLP_STS_AUDIENCE`, `AUDIT_OTLP_ENDPOINT` and `AUDIT_OTLP_AUDIENCE` and, deprecated for
  one minor, the same four as `ACCESS_ROSTER_*` until a build of the extension reads the new
  names. `Telemetry.OmitLegacyEnv` drops the old ones.
- **A stack gains a log metric filter and an alarm**, `<name>-writer-unknown-catalogue`
  (`AlarmNames` has an eighth entry), for records naming a catalogue version the writer lacks.
- **The root Go module no longer requires `github.com/truvity/sluis`.** An importer of
  `authn` uses `authn.SplitGroup` and `authn.ScopeAll`, which replace `policy.SplitGroup` and
  `policy.ScopeAll`.
- **`preset.ParseDeployment`** accepts the new `audit-deployment` group and the old one with a
  warning.

## Steps

### 1. Lambda: the stack

1. **Pin the release's zips** and bump the library to the same release
   ([ship a release](../aws-ship-a-release.md)). Verify: `pulumi preview` passes the guards.

2. **Add `Ingest.Senders`** (and `Redrivers` for an operator role), as role ARNs. Verify: the
   preview shows the queue policy gaining the deny with the senders as exceptions. Roll back:
   `Ingest.AnySenderInAccount: true` is the acknowledged alternative for a trial, never together
   with `Senders`.

3. **Move secrets to SSM.** Replace a variable the function read a secret from by a SecureString
   under the `SecretsRoot` output, and name it in `Writer.Keys` (`tokenSecret: openbao/token` is
   `<root>/openbao/token`) ([store the writer's secrets in SSM](../aws-store-secrets-in-ssm.md)).
   Verify: the first invocation of the new version starts. Roll back: `pulumi up` the previous
   program; the previous layer version is kept.

4. **Catalogues** need no rename: any `*.yaml` document is a catalogue
   ([change what a source records](../change-what-a-source-records.md)).

### 2. Kubernetes: the values

1. **Migrate each `config:` to version 2.** Set `apiVersion: audit.truvity.github.io/<kind>/v2`;
   rename `passwordEnv`, `credentialsEnv` and `tokenEnv` to `passwordSecret`, `credentialsSecret`
   and `tokenSecret`; and add the one `secrets` block:
   `secrets: {source: file, root: /etc/audit/secrets}` with the component's `secretEnv` entries
   replaced by `secretFiles` entries whose `name` is the file name (`AUDIT_DATABASE_PASSWORD`
   becomes, say, `database-password`). To keep reading environment variables instead, add
   `secrets: {source: env}` and leave `secretEnv` (deprecated). The chart's values schema accepts a
   config in version 2 when it says so and in version 1 otherwise, so existing values render as
   before. Verify: `helm template` renders and the parts start. Roll back: restore the version-1
   config; it is still read, with a deprecation warning per converted field.

2. **Check the probes** (`/readyz`) and any alerts you wrote against readiness.

### 3. Files outside the chart

A version-1 file (`truvity.github.io/<kind>/v1`, or no `apiVersion`) is validated against its
frozen schema (`schemas/config/v1/`), converted, validated against version 2's, read, and logs a
deprecation warning. The schemas' `$id`s move to
`https://truvity.github.io/audit/schemas/v2/config/<kind>.schema.json`; version 1's stay under
`.../schemas/v1/config/`. A file with another group, version or kind is refused by name.

## Afterwards

- Delete the version-1 spellings before the **next minor**, which removes the reading of them.
- Watch `event=unknown_catalogue` and the new alarm for the first day.
- The detailed entries are in the [CHANGELOG](../../../CHANGELOG.md#unreleased).
